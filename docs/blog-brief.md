# Blog brief: GreekInk, a Greek handwriting keyboard for the iPad

Source material for a blog post. Everything here is fact from the project (code, git history,
measurements on the device, official docs). Numbers were measured on the real iPad unless
marked otherwise. The author is a senior mobile engineer (12 years, mostly React Native and
TypeScript) who built this with Claude Code as a personal project.

## One-paragraph summary

Apple Pencil's Scribble turns handwriting into text in any text field on the iPad, in more
than 40 languages, but not Greek, and there is no API to add a language. GreekInk fills that
gap with a custom keyboard: you write Greek on a strip at the bottom of the screen and the
words appear wherever the cursor is, in any app. Recognition runs on the device with Google
ML Kit Digital Ink, so your handwriting and your text never leave the iPad. The keyboard needs
no "Full Access" and uses about 9 MB of memory. From an empty folder to a working keyboard on the iPad took one
afternoon and evening (first commit 17:42, first keyboard test passed 21:29, 5 Nov 2026).

## Test setup

iPad Air 5th generation (M1), iPadOS 27.0.1, Apple Pencil [model: fill in], Google ML Kit
Digital Ink 8.0.0 (CocoaPods `GoogleMLKit/DigitalInkRecognition` 9.0.0), Xcode 27.2 on macOS
26.6.2. All timings and memory numbers come from this one device. The ~90 MB keyboard memory
limit was measured on this M1 iPad; older iPads may allow less.

## Privacy, stated precisely

Your handwriting and your text never leave the iPad. The keyboard has no network at all: a
keyboard without Full Access can't open a connection. The app goes online only to download the
model, and ML Kit sends Google basic usage metrics from it. Google's ML Kit terms say input is
processed fully on the device and is not sent to Google, but the APIs may contact Google for
bug fixes and updated models, and they send metrics on how the APIs perform and are used.
Source: https://developers.google.com/ml-kit/terms

## The problem

- The author writes Greek by hand on an iPad with an Apple Pencil and wants typed text out of it,
  in any app (Notes, Mail, messages), not only inside one note-taking app.
- Scribble (Apple Pencil handwriting to text) on iPadOS 27 supports 44 language variants:
  Arabic, Chinese, Japanese, Korean, Thai, Ukrainian, Russian, Turkish, most European languages.
  Greek is not on the list. Source: Apple's "iOS and iPadOS 27 – Feature Availability" page.
- Apple's built-in handwriting *keyboards* exist only for Chinese (Simplified, Traditional),
  Cantonese and Japanese. Greek has a typing keyboard only.
- There is no API for adding a Scribble language. The only way in is a custom keyboard
  extension, a mini app that iOS shows instead of the system keyboard.
- What is on the App Store: one general "Handwriting Keyboard" app claims 100+ languages
  including Greek. It is free with in-app purchases from $2.99 to $49.99, shows ads, and its
  privacy label lists tracking (identifiers, usage data) for third-party advertising. MyScript
  Stylus, the best-known handwriting keyboard, has been retired.

## The idea in one picture

Pencil strokes (x, y, time) → keyboard extension → ML Kit Digital Ink, Greek model, on device
→ top candidate inserted into the text field → alternatives in a bar above the strip.

ML Kit works on strokes with timestamps, not on images, which is why it is fast and accurate
for live handwriting. Its Greek model is about 22 MB once unzipped.

## Decisions and why

- **Native Swift, not React Native.** A keyboard extension has a hard memory limit and iOS
  kills it without warning when it goes over. A JavaScript runtime would eat most of it.
- **Custom keyboard extension, not a standalone app.** Only a keyboard can put text into any
  app. The standalone app (write, then copy and paste) was kept as Plan B.
- **Google ML Kit Digital Ink.** It has on-device Greek and English models, is free, and
  handles accents. Apple's own handwriting recognition has no Greek and no public API.
- **Free Apple "Personal Team" signing.** No paid developer account. The cost: every install
  stops launching after 7 days and must be re-installed from the Mac with one script.
- **Work in phases with a stop after each:** setup (prove signing and the riskiest platform
  limits on the real device first), prototype app, keyboard, polish. Risky unknowns were tested
  before anything was built on top of them.
- **Everything generated from text files.** The Xcode project is generated by XcodeGen from
  `project.yml`. The signing team lives in one git-ignored file, so another team on the same
  Apple ID can never be picked by accident.

## The risks at the start, and what happened

| Risk | Fear | Result |
|---|---|---|
| Memory limit of keyboards | Folk wisdom says 48–60 MB; ML Kit model ~20 MB | Measured limit on an iPad Air M1: ~90 MB (older iPads may have less). With the Greek model loaded the keyboard uses 9.2 MB (the model file is memory-mapped, so it barely counts) |
| No network in the keyboard | A keyboard without Full Access cannot download the model | Solved by having the app download it and share it (see below). No Full Access needed |
| App Groups on a free account | Shared storage might need a paid account | Works on the free Personal Team |
| Keyboard can't write shared storage | Without Full Access it can only read | Confirmed read-only, designed around it |
| ML Kit inside an extension | It might use APIs extensions can't | Links, loads and recognises fine |
| Apple Pencil in a keyboard | Pencil touches might not arrive | They arrive, drawing is smooth |
| Greek accuracy | τόνος, dialytika, final ς, capitals | Long sentences come out right, including "Μαΐου" (dialytika with tonos) |

## The hard parts (good story material)

1. **Getting the model into the keyboard without the internet.** ML Kit stores downloaded
   models in the app's private folder and offers no setting to look elsewhere. The keyboard is
   a separate process with its own private folder and no network. The fix: the app copies ML
   Kit's whole model folder into the shared App Group container; the keyboard copies it into its
   own private folder before ML Kit starts. Reading ML Kit's files on the device showed one
   catch: the download manager names its metadata files after the app's bundle ID
   (`com.….greekink.com.google.mlkit.mdd…`), and the keyboard has a different bundle ID. So the
   keyboard also writes renamed copies. It worked on the first try. On Apple's file system the
   "copy" of 71 MB is a clone and takes 13 ms. The 71 MB is everything ML Kit keeps for both
   languages: the Greek model unzipped (22 MB), the English model unzipped (25 MB), and the
   zipped downloads of both that ML Kit keeps next to them (24 MB).
2. **The palm that ate the Pencil.** In the full-screen test app the Pencil sometimes drew
   nothing. The diagnostics log showed why: the resting palm touched the screen first and took
   the only touch slot, so Pencil touches were never delivered. The canvas now accepts several
   touches, lets the Pencil take over from a finger, ignores finger touches for 1.5 s after
   Pencil contact, and ignores touches wider than a fingertip. Measured touch radius: palm
   52–62 pt, fingertip 20–25 pt, Pencil 0. Result: 101 Pencil strokes in a row, all recorded.
3. **A crash inside ML Kit.** ML Kit 8.0.0 declares the "text before the cursor" parameter as
   optional, but passing nothing crashes its recognition thread (a C `strlen` on a null
   pointer, found in the crash log pulled off the iPad). Always pass an empty string.
4. **Latin words in Greek text.** The first long test sentence in the app was, fittingly,
   "Αφού η Apple δεν υποστηρίζει ελληνικά, δεν είμαι κορόιδο να αγοράσω αλλά έφτιαξα εφαρμογή"
   ("Since Apple doesn't support Greek, I'm not a sucker to buy one, so I built an app"). Everything
   came out right except "Apple δεν", which became "Αρρα δω". ML Kit has no mixed Greek/Latin
   model, so the keyboard got an ΕΛ/EN key that switches models. Later tests were kinder: the
   Greek model read "Apple" on its own, "Η Apple", and "Hello, αγάπη μου!" with both scripts.
   (Optional quote; check with the author before using the sentence.)
5. **Tool friction.** XcodeGen writes a newer Xcode project format than CocoaPods can read, so
   the generator post-processes the file. The free signing team's ID was being copied into the
   generated project file and so into git; the generator now strips it.
   ML Kit is only on CocoaPods, whose central repository stops accepting new versions on
   2 Dec 2026. What that means here: nothing breaks. The project pins ML Kit 9.0.0 in
   `Podfile.lock`, and existing pods keep installing after the freeze. What it costs: no ML Kit
   updates through CocoaPods after that date. The plan: stay on the pinned version, switch if
   Google ships ML Kit as a Swift package, and keep a copy of the ML Kit frameworks as a fallback.
   Source: https://blog.cocoapods.org/CocoaPods-Specs-Repo/
6. **One candidate instead of five.** The first keyboard test showed a single suggestion.
   A warm-up recognition at startup asked ML Kit for one result, and the cached recognizer kept
   that setting. Found from the keyboard's own log, fixed in minutes.
7. **The gesture model that wasn't there.** Google's model table lists a Greek gesture
   classifier (`el-x-gesture`) for scratch-out gestures. On the iPad the download failed with
   "unknown model tag". The model list compiled into the iOS SDK has only the text languages
   plus emoji, shapes and auto-draw. So the zigzag is detected with plain geometry: one wide,
   flat stroke that sweeps across most of its width at least three times. Tuning it took three
   rounds of logs. The first rule (five direction changes) missed every real zigzag, which had
   four. The second deleted a line break instead of a word. Then a tiny dot left by the Pencil
   just before the zigzag counted as "ink to erase". Each verdict is logged with turns, sweeps
   and size, and normal Greek writing never triggered it.
8. **Digits next to letters.** "1η" (1st) came out as "ξη". ML Kit has no digits-only model,
   so a 123 key switches the keyboard into number mode. Candidates made of digits move to the
   top, look-alikes are converted (Ο→0, ι→1, Ζ→2), and digits join without the automatic space,
   so "15:" + "30" gives "15:30". A row of punctuation keys sits above the strip as well.
9. **Going public safely.** Before the repo went public, a scan found the signing Team ID, the
   iPad's device ID with the owner's first name, and a personal email as the author of every
   commit. The history was rewritten to scrub them and use GitHub's no-reply address, with the
   commits and messages kept, and checked file by file before the force-push.

## How the keyboard behaves

- Write a word or several, pause 800 ms (long enough to add a τόνος after the letters): the
  best candidate is inserted with an automatic space, the ink clears, and up to five
  alternatives appear above the strip. Tap one to swap it in.
- Backspace removes the last stroke while there is ink, otherwise deletes text; hold to repeat.
- ΕΛ/EN switches models. Globe key switches keyboards. Light and dark follow the text field.
- The last 20 characters before the cursor are passed to ML Kit as context.
- A zigzag on the strip erases the ink; on an empty strip it deletes the last word.
- A row of punctuation keys (. , ; · ! ? : ' " ( ) -) and a 123 key for digits and number mode.
- In Notes, Apple's own Scribble scratch-out also deletes the inserted words. It works even
  though Scribble can't read Greek handwriting. The user discovered this while testing.

## Accuracy (rough count)

From the keyboard's own logs over several test sessions (5–6 Nov), counting only the 26 writes
where the intended text is obvious, all by one writer:

| Result | Writes |
|---|---|
| Right first time | 20 (77%) |
| Wrong at first, right answer one tap away in the candidate bar | 5 |
| Wrong, right answer not offered | 1 (before context was added) |

Writes were mostly words and short phrases. Five writes with unclear intent are left out.
Almost every miss was a single letter: ν→μ, "1η"→"ξη", "μας"→"μιας", "σου"→"συ",
"Nature"→"Natur". For the post, a cleaner test would help: 20 written sentences, counted by
the author.

## Misreads so far (honest part)

- "Καλημέρα αγάπη μου!" → "Καλημέρου αγάπη μου!" (final α read as ου), finger.
- "Καλημέρα αγάπη μου Μαΐου" → "Καλημέρα γάπη του Μαΐου" (leading α dropped, μ read as τ), Pencil.
- "νερό στη βάρκα μας" → "μερό στη βάρκα μας" (ν read as μ), Pencil, in the keyboard.
- Accents, dialytika and capitals were right every time.
- With context switched on, the same "νερό στη βάρκα μας" came out right, and so did "Παράπονο",
  "μέμφομαι" and "ωραίο". Near misses: "Natur boy" for "Nature boy", and "μιας" for "μας" once.
- The user's verdict on punctuation and number mode: "works great and intuitively".

## Can I use it?

Yes, if you have a Mac. It isn't on the App Store, so you build it yourself:

- **The catch, up front:** with a free Apple ID the app stops launching after 7 days. Plug the
  iPad in and run one script to reinstall; settings and the model survive.
- **You need:** a Mac with Xcode 27.2 or newer and CocoaPods, a free Apple ID signed in to
  Xcode, an iPad with iPadOS 17 or newer, a USB cable. An Apple Pencil is best; a finger works.
- **Steps:** clone the repo, follow the README (about 10 minutes the first time, mostly the
  first build), then add the keyboard in Settings. No "Full Access" needed.
- README: https://github.com/altany/apple-greek-handwriting#readme

## How it was built (the AI-pair angle)

- Built with Claude Code in a terminal. The human tested on the iPad and made the calls; the
  agent wrote the code, built, signed, installed on the iPad over USB, and read the results.
- `CLAUDE.md` in the repo is the project's memory: decisions, risks, measurements, findings,
  current status. Each session starts by reading it, which is how work resumed across days.
- Test rounds without screenshots: the app and keyboard write diagnostics logs, and the agent
  pulls them (and crash logs) off the iPad with `xcrun devicectl`. The human writes on the
  iPad, says "done", and the agent reads what happened.
- The human answered most questions with one word through option dialogs. Anything touching the
  Apple account, GitHub settings or global installs needed an explicit yes first.
- Before building the keyboard, the agent read ML Kit's files on the device to see how the
  download manager names its files. That is how the bundle-ID rename was known in advance, and
  why the shared model worked on the first try.
